TypeScript agents get the same zero-config instrumentation as Python. Install the package
matching your framework; each depends on the shared `@agentegrity/client` core.

```bash
npm i @agentegrity/claude-sdk      # Claude Agent SDK
npm i @agentegrity/langchain       # LangChain JS / LangGraph JS
npm i @agentegrity/openai-agents   # OpenAI Agents SDK
npm i @agentegrity/crewai          # CrewAI JS
npm i @agentegrity/google-adk      # Google ADK
npm i @agentegrity/vercel-ai       # Vercel AI SDK (TypeScript-native)
```

Works under Node, Bun, and the browser. `bun`, `npm`, `pnpm`, and `yarn` all resolve the
same published versions.

## Architecture

<Steps>
  <Step title="Framework glue">
    Each `@agentegrity/<framework>` package is under 100 lines: it wires the framework's
    native hook to `emit()` and re-exports the shared lifecycle helpers.
  </Step>
  <Step title="createDefaultAdapter">
    A lazy singleton in `@agentegrity/client` mirroring the Python `_BaseAdapter`: one
    session id per adapter, fail-open exporter fan-out, idempotent start/end, and a
    `process.beforeExit` shutdown hook so `session_end` fires on clean exit.
  </Step>
  <Step title="AgentegrityReporter">
    Emits the published wire format over HTTP to any backend implementing
    `schemas/openapi.yaml`.
  </Step>
</Steps>

## Important difference from Python

<Warning>
  The TypeScript packages are **reporters**, not evaluators. They emit the same event stream
  and the same topology types, but the four-layer evaluation runs on whatever backend
  receives the events: they do not run the layers in-process.

  Practically: no in-process `enforce=True`, no local attestation chain. If you need
  in-process evaluation, run the Python library.
</Warning>

## Configuration

Everything comes from the environment, so nothing changes in your agent code:

| Variable | Effect |
|---|---|
| `AGENTEGRITY_URL` | Backend base URL. Defaults to `http://localhost:8787` |
| `AGENTEGRITY_TOKEN` | Bearer token for `Authorization` |
| `AGENTEGRITY_DISABLED` | `1` or `true` disables the adapter entirely |

<Info>
  **The token is TLS-gated.** It is only sent when `baseUrl` is HTTPS or a loopback host
  (`localhost`, `*.localhost`, `127.0.0.1`, `::1`). Anything else (including a URL that fails
  to parse) is treated as unsafe and the credential is withheld, so a misconfigured
  `http://remote` endpoint never leaks it.
</Info>

## Common surface

Every package re-exports the same four:

```ts
import { report, reset, registerExporter, adapter } from "@agentegrity/langchain";

report();               // SessionSummary snapshot
reset();                // discard session state; next emit starts fresh
registerExporter(e);    // add a SessionExporter subscriber
adapter();              // the underlying DefaultAdapter
```

## Writing an exporter

```ts
import { registerExporter } from "@agentegrity/langchain";
import type { SessionExporter } from "@agentegrity/client";

const consoleExporter: SessionExporter = {
  async onSessionStart(sessionId, adapterName, profile) {
    console.log(`[${adapterName}] session ${sessionId} started`);
  },
  async onEvent(sessionId, event) {
    console.log(" ", event.event_type, event.evaluation_result?.action);
  },
  async onSessionEnd(sessionId, summary) {
    console.log(`[${sessionId}] ${summary.events} events`);
  },
};

registerExporter(consoleExporter);
```

Fan-out is fail-open: `safeCall` catches and logs every exporter error, so a broken
subscriber can never break the agent. Registration is idempotent by reference equality.

## Custom frameworks

Drop to the reporter directly:

```ts
import { AgentegrityReporter } from "@agentegrity/client";

const reporter = new AgentegrityReporter({
  baseUrl: process.env.AGENTEGRITY_URL!,
  apiKey: process.env.AGENTEGRITY_TOKEN,
  adapterName: "my-framework",
  profile: {
    agent_id: "my-agent",
    name: "my-agent",
    agent_type: "tool_using",
    capabilities: ["tool_use"],
    deployment_context: "cloud",
    risk_tier: "medium",
    framework: "my-framework",
    model_provider: null,
    model_id: null,
    metadata: {},
  },
});
```

## Version parity

`scripts/check-versions.ts` (TypeScript) and `scripts/check_versions.py` (Python) are both
wired into CI, keeping `pyproject.toml`, `src/agentegrity/__init__.py`, every
`package.json`, and the README badge from drifting apart.

The release workflow publishes the Python wheel and all npm packages in one matrix, so a
version number means the same thing in both ecosystems.

## Conformance

`clients/typescript/test/cross-package-conformance.test.ts` runs 52 tests across all six
packages, driving the same shared-core seam through the same canonical event stream as the
Python suite. Total TS test count is 117 (52 conformance + 65 per-package).

Two invariants are pinned as absences: `claude-sdk` and `vercel-ai` must **never** declare a
topology, and the four multi-agent-capable packages must expose `setTopology`.
