```bash
agentegrity report --trusted-key agent.pub chain.json
agentegrity report --format json -o audit.json chain.json
```

The report turns a serialized chain into something an assessor can read: verification status,
a record timeline, a human-approvals table, and a control mapping.

## Options

| Flag | Effect |
|---|---|
| `--format markdown\|json` | Output format. Default `markdown` |
| `-o`, `--output <path>` | Write to a file instead of stdout |
| `--trusted-key <pub.hex>` | Pin a signing key. Repeatable. **Gates the exit code** |

### When signatures are unanchored

```markdown
- Signatures: yes [self-vouched]
  - Signatures are unanchored: pass `--trusted-key` to pin the signing
    identity. A self-vouched chain proves internal consistency, not authorship.
```

That caveat is printed in the report body, not just the terminal, so it travels with the
artifact to whoever reads it.

## The control mapping

| Framework | Control | Evidence in the report |
|---|---|---|
| **EU AI Act** | Art. 12 (Record-keeping) | Hash-linked record timeline; per-record content hashes; final chain hash |
| **EU AI Act** | Art. 14 (Human oversight) | Human Approvals section: approver identity, outcome, timeout behaviour per escalation |
| **NIST AI RMF** | GOVERN 1.2 (Policies) | Governance layer states embedded in attestation records |
| **NIST AI RMF** | MEASURE 2.7 (Security & resilience evaluated) | Integrity evaluations per boundary event |
| **NIST AI RMF** | MANAGE 4.1 (Post-deployment monitoring) | Continuous per-event attestation across the session |

<Warning>
  The report states this inline, and it matters: **this is supporting evidence, not a
  compliance determination.** Control applicability and sufficiency are judgements only an
  assessor can make.

  Do not present a generated report as a compliance attestation. Present it as the artifact an
  assessor uses to evaluate the controls.
</Warning>

## Human approvals

When escalations were put to a human, the table populates from `approval`-boundary
`DecisionRecord`s:

```markdown
| Tool | Outcome | Approver | Timed out |
|---|---|---|---|
| transfer_funds | approved | oncall@example.com | false |
| database_write | denied | oncall@example.com | true |
```

This is the section that maps to **EU AI Act Art. 14**, and it is only as good as your
approval wiring. A session run with `enforce=False`, or with `enforce=True` and no
`approval_handler`, produces an empty table.

<Info>
  Approvals are captured on the **adapter** enforcement path. `IntegrityMonitor` consults its
  handler to decide whether to block but does not write an approval decision record: so a
  monitor-based deployment shows an empty approvals table even when approvals happened.

  See [Enforcement and approvals](/docs/guides/enforcement-and-approvals).
</Info>

## Exit codes

| Situation | Exit |
|---|---|
| Everything verified | `0` |
| Hash linkage or decision links broken | `1` |
| Signatures failed **and** `--trusted-key` was passed | `1` |
| Signatures absent, no `--trusted-key` | `0`: disclosed in the report, not treated as tamper |
| Unreadable file / unparseable JSON / bad key | `2` |

<Warning>
  Structural tamper always fails. Signatures gate the exit code **only when you pinned a key**,
  because without an anchor no cryptographic claim was requested.

  In CI this means: **always pass `--trusted-key`**, or an unsigned chain exits `0`.
</Warning>

## In a release pipeline

```yaml
- name: Verify and report
  run: |
    agentegrity report \
      --trusted-key .agentegrity/agent.pub \
      --format markdown \
      -o artifacts/audit-report.md \
      artifacts/chain.json

- name: Upload audit artifact
  uses: actions/upload-artifact@v4
  with:
    name: agentegrity-audit
    path: artifacts/audit-report.md
```

## What is not in the report

Stated plainly so nobody infers coverage that is not there:

- **No prompts or tool arguments.** Decision records carry content **hashes** plus 120-character
  summaries. A chain is not a transcript.
- **No layer detail.** The report summarizes verification and timeline. Full `layer_states`
  live in the chain JSON itself.
- **No cross-agent verification.** The report covers one chain. Use
  `verify_cross_agent_links` with peer chains for a fleet.
- **No completeness proof.** A truncated chain reports clean. See
  [Verifying chains](/docs/guides/verifying-chains).

## Retention

The specification's control `VA-05` sets a **90-day minimum** for attestation record
retention. Chains are plain JSON, so retention is your storage policy: but keep the
corresponding public keys for at least as long, or the chains become unverifiable.
