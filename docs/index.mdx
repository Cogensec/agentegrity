title: "Agentegrity"
description: "Measure whether an AI agent keeps its integrity under adversarial pressure, and record every decision in a verifiable chain."
---

Agentegrity evaluates an agent from inside its own decision loop. An adapter hooks into the framework you already use, turns each prompt, tool call, tool result and handoff into an event, and scores it through four layers: adversarial, cortical, governance and recovery. Every evaluation and every decision is appended to a hash-linked attestation chain that you can sign and verify later.

The TypeScript packages report events and token usage without scoring them; the evaluation runs in the Python library and the coding-agent hook runtime.

The library runs locally and blocks nothing unless you turn enforcement on. Guardrails and runtime monitors filter what goes in and out of an agent; Agentegrity measures the assembled agent (model, prompts, tools, memory and peers) and produces evidence of what it did and why it was allowed.

## What you get from a session

- **Scores and verdicts.** Each event gets a composite score and an action (allow, log, alert, block or escalate), with the reason recorded. See [Scores and actions](/concepts/scoring-and-actions).
- **Decision provenance.** Decision records are captured at each decision boundary before the action runs, and can be verified from the command line. See [Attestation](/concepts/attestation).
- **Token usage.** The tokens a session spends, normalized across providers and totalled per model. See [Token usage](/concepts/token-usage).
- **Multi-agent structure.** Teams, crews, graphs and handoffs are declared as a topology that the chain commits to. See [Multi-agent systems](/concepts/multi-agent).
