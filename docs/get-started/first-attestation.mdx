A score you print to stdout is observational. An attestation chain is **evidence**: signed
records, each committing to the hash of its predecessor, independently verifiable by
someone who was not there when it was produced.

This walkthrough produces one end to end.

<Steps>
  <Step title="Install with signing support">
    ```bash
    pip install "agentegrity[crypto]"
    ```
    Without this extra, records are built and hash-linked but never signed.
  </Step>

  <Step title="Build a monitored agent">
    `IntegrityMonitor` wraps an arbitrary callable, evaluates before and after it runs, and
    appends an attestation for every evaluation.

    ```python first_attestation.py
    import asyncio

    from agentegrity import AgentegrityClient, IntegrityMonitor, ApprovalWorkflow
    from agentegrity.core.attestation import generate_signing_key

    client = AgentegrityClient()
    profile = client.create_profile(
        name="research-assistant",
        risk_tier="high",
        capabilities=["tool_use", "web_access"],
    )

    signing_key = generate_signing_key()          # Ed25519

    monitor = IntegrityMonitor(
        profile=profile,
        evaluator=client.evaluator,
        threshold=0.70,
        enable_attestation=True,
        signing_key=signing_key,
        approval_handler=ApprovalWorkflow(
            lambda p, score, action: True,        # replace with a real approver
            approver="oncall@example.com",
            timeout=30,
        ),
    )

    @monitor.guard
    async def agent_action(context=None):
        return "ok"
    ```
  </Step>

  <Step title="Run two boundaries">
    ```python
    async def main():
        await agent_action(context={
            "action": {"type": "tool_call", "tool": "web_search",
                       "arguments": {"q": "llm safety"}},
            "input": "summarize the latest papers",
        })
        await agent_action(context={
            "action": {"type": "tool_call", "tool": "database_write",
                       "arguments": {}},
            "input": "hello",
        })

    asyncio.run(main())
    ```

    The second call trips `GOV-001`: a `high` risk-tier agent touching a sensitive tool:
    which resolves to `escalate`. The `approval_handler` approves it, so execution proceeds.
    Remove the handler and the same call raises `IntegrityViolationError`: escalations
    **fail closed**.
  </Step>

  <Step title="Serialize and check the chain">
    ```python
    chain = monitor.attestation_chain

    print("records:   ", len(chain))
    print("hash-linked:", chain.verify_chain())
    print("signatures: ", chain.verify_signatures())

    open("chain.json", "w").write(chain.to_json())
    open("key.pub", "w").write(chain.records[0].public_key.hex())
    ```

    ```text
    records:    4
    hash-linked: True
    signatures:  (True, None)
    ```

    Four records: a pre- and post-execution attestation for each of the two calls.
    `verify_signatures()` returns `(ok, first_bad_index)`.
  </Step>
</Steps>

## Verify it from the CLI

The chain is a plain JSON file. Anyone with the file and the public key can check it:
no library state, no network.

```bash
agentegrity verify-decisions --trusted-key key.pub chain.json
```

```text
agentegrity 0.10.0 — verify-decisions chain.json
  records:        4
  chain linkage:  yes (hash-linked)
  decision links: yes
  signatures:     yes [pinned]

  idx  kind          boundary/score          tier      signed  verified
    0  attestation   attestation             -         yes     yes
    1  attestation   attestation             -         yes     yes
    2  attestation   attestation             -         yes     yes
    3  attestation   attestation             -         yes     yes
```

<Warning>
  Drop `--trusted-key` and the anchor line reads `[self-vouched]` instead of `[pinned]`.
  Every record embeds its own public key, so a chain forged wholesale with an
  attacker-generated key verifies against itself perfectly. **A self-vouched chain proves
  internal consistency, not authorship.** Always pin a key where the chain crosses a trust
  boundary.
</Warning>

## Render an audit report

```bash
agentegrity report --trusted-key key.pub chain.json
```

```markdown
# Agentegrity Session Audit Report

- Source: `chain.json`
- Generated by: agentegrity 0.10.0
- Records: 4
- Final chain hash: `55f8365602b6477a2c295327737165f787d91c4728ff21ff8a0414f7bb53b63a`

## Verification

- Hash linkage: yes
- Decision links: yes
- Signatures: yes [pinned]

## Record Timeline

| # | Kind | Boundary | Tier | Signed | Content hash |
|---:|---|---|---|---|---|
| 0 | attestation | attestation | - | yes | `e14884f658103d87…` |
...
```

The report also carries a **Compliance Evidence Mapping** section tying the chain's
artifacts to EU AI Act Art. 12 / Art. 14 and NIST AI RMF controls. It is framed as
supporting evidence, explicitly **not** a compliance determination. See
[Compliance reports](/docs/guides/compliance-reports).

Exit codes matter in CI:

- Structural tamper (broken hash linkage or a dangling decision link) **always** exits `1`.
- Signature failures gate the exit code **only when `--trusted-key` is passed**: without an
  anchor, no cryptographic claim was requested, so an unsigned chain is disclosed in the
  report rather than treated as tampered.

## Prove tamper-evidence to yourself

```python
from agentegrity import AttestationChain

chain = AttestationChain.from_json(open("chain.json").read())
record = chain.records[1]
record.integrity_score["composite"] = 0.99      # forge a better score

print(chain.verify_chain())          # False — record 2's link no longer matches
print(chain.verify_signatures())     # (False, 1) — signature covers the payload
```

The signature covers the canonical payload **including `chain_previous`**, so editing any
record breaks both the link to its successor and its own signature.

## What actually happened

Each `@monitor.guard` call ran the full four-layer pipeline, produced an `IntegrityScore`,
and appended an `AttestationRecord` carrying:

- the complete score (composite, per-property, per-layer)
- `layer_states`: the full detail dict from every layer
- one `Evidence` entry per layer result, hashed with SHA-256 over canonical JSON
- `chain_previous`: the predecessor's content hash, baked in **before** signing

<Info>
  Adapters do more than the standalone monitor: at `pre_tool_use`, `stop`, and
  `subagent_start` they also append a [`DecisionRecord`](/docs/concepts/decision-provenance)
  capturing the candidate action *before* it executes, and the next attestation commits to
  it via `Evidence(evidence_type="decision")`. That is what `decision links: yes` checks.
</Info>
