# Agentegrity v0.13.0 — release go/no-go ledger

**Decision: NO-GO for registry publication.** This is an evidence ledger
for a future approval decision, not an approval, vulnerability waiver, or
statement that upstream code is patched.

The `v0.13.0` source and all seven npm workspace packages are staged on
`main`; the latest published GitHub release is v0.12.0 as checked on
October 21, 2026. A `v0.13.0` tag triggers automatic TestPyPI,
PyPI and npm publication. **Do not create a tag as a validation step.**

## Supported integration dependency boundaries

| Scope | Finding and disposition | Publication decision |
| --- | --- | --- |
| Base Python wheel | Zero mandatory runtime dependencies; clean-wheel installation and artifact inspection included in candidate verification | Can be built; this does not clear optional extras |
| Modern seven-package npm workspace | No direct runtime vendor dependency beyond `@agentegrity/client`; Undici 6/7 and esbuild patch floors guarded | Keep modern SDK checks and pack validation |
| Optional CrewAI integration | Published CrewAI 1.15.28 resolves ChromaDB 1.5.9, MCP 1.28.1 and uv 0.11.33 with documented vulnerabilities | **OPEN — blocks publication** |
| Legacy AI SDK v5 consumers | Supported optional peer may install Undici 5.29.0 and Busboy 2.1.1 with known advisories | **OPEN — blocks publication** |

The release workflow runs real optional CrewAI and isolated AI SDK v5
audits in the **hard** `optional-dependency-security-gate` job.
`publish-testpypi` requires that job to succeed, and all subsequent
publication jobs depend on TestPyPI. A nonpublishing rehearsal confirmed
that the gate rejects current findings. Do not confuse a successful
rehearsal job (which intentionally emits a warning) with an approved
release.

## Explicit conditions for release approval

- [ ] **Vendor dependency fixes:** CrewAI publishes metadata compatible
  with fixed MCP and uv versions and a patched ChromaDB release with
  fixed-version advisory evidence, or a separately reviewed, fully
  documented deployment-risk disposition is explicitly approved by
  the designated security owner.
- [ ] **Legacy AI SDK v5:** vendor-maintained patch or validated support
  transition. Do not silently drop advertised compatibility, and do
  not ship the experimental Undici 6 override simply because an
  isolated audit is clean.
- [ ] **Release security gate:** full optional-framework audit exits
  zero *without ignored findings*, or a narrowly documented exception
  has been explicitly approved and reviewed as a separate change.
- [ ] **Artifact test gate:** latest commit passes Python 3.10/3.12,
  code checks, TypeScript Node 18/20/22, isolated AI SDK v5 tests,
  CodeQL, wheel/sdist smoke, all seven npm pack checks and coverage.
- [ ] **Registry readiness:** TestPyPI, PyPI and npm GitHub environment
  approvals/trusted publishing configuration reviewed by a release
  owner. Artifact metadata and `v0.13.0` name availability verified.
- [ ] **Human go:** an authorized release owner explicitly approves
  publishing the exact release commit and version *after* all security
  decisions are recorded.

## One-way release execution when GO is signed

1. Record approval and the validated commit SHA in the release issue.
2. Freeze the commit after all final checks; ensure no newer changes
   have invalidated the evidence.
3. Create `v0.13.0` tag on that exact commit only after approval.
4. Confirm the release GitHub Actions run passes the security gate
   and the environment-gated TestPyPI, PyPI, npm client and six npm
   adapter jobs. Stop and investigate any partial registry publication.
5. Smoke-test installed artifacts from the registries and publish
   a changelog only after the corresponding artifacts exist.

**No registry publication or risk acceptance is authorized by this
document.** The security owner may decline an exception and wait for
vendor-maintained releases. Keep
[issue #97](https://github.com/Cogensec/agentegrity/issues/97)
open until the decision is based on supported evidence.
