# v0.13.0 dependency advisory triage — OPEN release gate

**Status: not cleared for registry publication.** Audits ran against the
v0.13.0 release-candidate branch on October 20, 2026. The TypeScript
security-patch refresh in PR #96 now upgrades in-range Undici 6.x/7.x and
esbuild development tooling, but **optional-framework exposure remains open**.
This is a scoped remediation, not a clean global audit.
[GitHub CI audit job](https://github.com/Cogensec/agentegrity/actions/runs/39516349952)
was displayed as successful **because both audit commands are configured
with `continue-on-error: true`**.

## Exposure boundary

The base Python project declares **zero mandatory runtime dependencies** in
`pyproject.toml`. The Python audit installed **all optional framework extras
and dev dependencies** via `pip install -e ".[all,dev]"`, so these findings
are not necessarily inherited by users running only `pip install agentegrity`.

Each of the seven npm packages declares the shared `@agentegrity/client`
as its only runtime dependency (the client declares no runtime dependencies);
framework SDKs are optional peers or workspace dev dependencies. The full
Bun audit includes tooling, testing, optional framework peer SDKs and their
transitive dependency trees. **This reduces direct package exposure but
does not prove deployed applications are safe.** A user may install the
affected peer SDK or run a vulnerable ingestion endpoint.

Reverse-dependency paths have been collected in a dedicated CI artifact.
The Bun-generated lockfile has now been refreshed and tested against the
target patch floors. Some optional SDKs still require vulnerable dependency
lines; compatibility and release-risk acceptance remain open.

## Verified reverse-dependency paths

The [nonpublishing package-check workflow](https://github.com/Cogensec/agentegrity/actions/runs/39519105852)
captured `pipdeptree` and `bun why` inventories on October 20–21, 2026.
The findings below are grounded in those installed **test** environments:

**Python (from `pip install -e ".[all,dev]"`):**

- `chromadb==1.5.9` ← `crewai==1.15.28` requires
  `chromadb~=1.5.9`. The reported four distinct advisories have **no
  patch version in the scanned index**, and CrewAI pins the affected series.
- `mcp==1.28.1` ← `crewai==1.15.28` requires
  `mcp~=1.28.1`; also ← `claude-agent-sdk==0.2.169`,
  `openai-agents==0.20.0`, `strands-agents==1.61.1`. CrewAI's pinned
  1.28.x range **does not permit** the reported 1.30.0 fix without an
  upstream dependency change.
- `uv==0.11.33` ← `crewai-cli==1.15.28` requires
  `uv~=0.11.6` ← `crewai==1.15.28`. The declared range does **not
  allow** the 0.13.4 patched version without a CrewAI upstream change.

**npm (from frozen `clients/typescript/bun.lock`):**

- `@fastify/busboy@2.1.1` ← `undici@5.29.0` ←
  `@ai-sdk/provider-utils@3.0.41` ← `ai@5.0.272` ←
  **dev-only** `@agentegrity/vercel-ai` compatibility test alias
  `ai5`. Avoid forcing a major Busboy upgrade into Undici v5 without
  verifying the API: this is not a shipped direct runtime dependency.
- `undici@6.29.1` ← AI SDK v6 developer/optional peer dependency and
  OpenAI SDK / LangSmith optional peers in the TypeScript test workspace;
  `undici@7.30.1` ← **dev-only** AI SDK v7 compatibility test alias.
  Bun 1.3.10 regenerated these entries and integrity checks after
  invalidating only their stale locked records; scoped semver-compatible
  selectors preserve the patched floors. The `undici@5.29.0` line
  remains via AI SDK v5's unpatched legacy dependency chain.
- `esbuild@0.28.2` ← `tsx@4.23.15` ← TypeScript workspace and adapter
  **devDependencies**. Both are now above their verified patch floors;
  the source manifest declares `tsx ^4.23.9`.
- `uuid@11.1.1` ← Google ADK via A2A JS SDK; **also** `uuid@9.0.1` ←
  `gaxios@6.7.1` ← Google ADK's developer dependency tree. The 9.x copy
  means we must not dismiss the audit warning simply because 11.1.1 is
  also present.

**Interpretation:** The base Python wheel is dependency-free and installed
successfully in a fresh environment. All seven npm packages were inspected
with `npm pack --dry-run`, and their declared production dependency edges
contain only `@agentegrity/client` (or none, for the client). Those facts
reduce *direct distribution* exposure; they do **not** remove vulnerabilities
in consumer-selected framework peers or installations of the optional
`crewai` extra.

## Required actions before release sign-off

1. **Complete:** isolated base-only Python wheel install and all-extras
   `pipdeptree --reverse --packages chromadb,mcp,uv` inventory captured.
   Retain this as release evidence and inspect upstream constraints.
2. **Complete:** `bun why @fastify/busboy`, `bun why undici`,
   `bun why esbuild`, and `bun why uuid` captured. Separate dev-only,
   optional peer, and direct runtime edges as described above. All seven
   npm package dry-run contents passed source-version/package checks.
3. **Partial completion:** the generated `clients/typescript/bun.lock`
   now contains `undici@6.29.1`, `undici@7.30.1`, `esbuild@0.28.2`
   and `tsx@4.23.15`. TypeScript type checks, build, tests, coverage
   and all seven npm package dry runs passed in the refresh workflow.
   A permanent CI patch-floor check guards against regression. The
   **AI SDK v5 → Undici 5 → Busboy 2** chain is still unresolved.
   Do not force a major `@fastify/busboy` override without upstream
   compatibility evidence.
4. Re-run Python and Bun vulnerability scans and capture the results. For
   packages without patches, record a clear *owner, exposure analysis,
   restrictions and explicit acceptance*; do not mark an advisory silently
   resolved just because the audit CI job is green.
5. Validate wheel/sdist + all seven npm package contents in the new
   nonpublishing package verification CI before creating any release tag.
6. Obtain explicit release authorization. **Pushing a `v*.*.*` tag automatically
   initiates registry publication** in `.github/workflows/release.yml`.

## Validated TypeScript patch evidence (PR #96)

The [Bun 1.3.10 refresh run](https://github.com/Cogensec/agentegrity/actions/runs/39522467499)
verified `undici@6.29.1`, `undici@7.30.1`, and `esbuild@0.28.2`.
All TypeScript adapter tests, coverage and package-content checks passed.
The resulting lockfile was committed to PR #96 by a scoped, temporary
nonpublishing workflow. Future CI checks the required patched floors.

This **does not** fix unpatched CrewAI/ChromaDB optional dependencies,
CrewAI's incompatible MCP/uv pins, or AI SDK v5's legacy Undici/Busboy
chain. CI's audit remains advisory: it does not clear the release gate.

## Current decision

**Prepared and mergeable release infrastructure is not the same thing as
approved distribution.** This triage is intentionally open. Closing this
release gate requires evidence of fixes or a documented, approved decision
about the affected optional dependency paths. Do not claim "0 known
vulnerabilities" and do not publish v0.13.0 on the strength of a green
advisory-only job.
