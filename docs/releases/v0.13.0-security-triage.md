# v0.13.0 dependency advisory triage — OPEN release gate

**Status: not cleared for registry publication.** Audits ran against the
v0.13.0 release-candidate branch on October 20, 2026. The TypeScript
security-patch refresh in PR #96 now upgrades in-range Undici 6.x/7.x and
esbuild development tooling, but **optional-framework exposure remains open**.
This is a scoped remediation, not a clean global audit.
[GitHub CI audit job](https://github.com/Cogensec/agentegrity/actions/runs/39516349952)
was displayed as successful **because both audit commands are configured
with `continue-on-error: true`**.

## Exposure boundary

The base Python project declares **zero mandatory runtime dependencies** in
`pyproject.toml`. The Python audit installed **all optional framework extras
and dev dependencies** via `pip install -e ".[all,dev]"`, so these findings
are not necessarily inherited by users running only `pip install agentegrity`.

Each of the seven npm packages declares the shared `@agentegrity/client`
as its only runtime dependency (the client declares no runtime dependencies);
framework SDKs are optional peers or workspace dev dependencies. The full
Bun audit includes tooling, testing, optional framework peer SDKs and their
transitive dependency trees. **This reduces direct package exposure but
does not prove deployed applications are safe.** A user may install the
affected peer SDK or run a vulnerable ingestion endpoint.

Reverse-dependency paths have been collected in a dedicated CI artifact.
The Bun-generated lockfile has now been refreshed and tested against the
target patch floors. Some optional SDKs still require vulnerable dependency
lines; compatibility and release-risk acceptance remain open.

## Verified reverse-dependency paths

The [nonpublishing package-check workflow](https://github.com/Cogensec/agentegrity/actions/runs/39519105852)
captured `pipdeptree` and `bun why` inventories on October 20–21, 2026.
The findings below are grounded in those installed **test** environments:

**Python (from `pip install -e ".[all,dev]"`):**

- `chromadb==1.5.9` ← `crewai==1.15.28` requires
  `chromadb~=1.5.9`. The reported four distinct advisories have **no
  patch version in the scanned index**, and CrewAI pins the affected series.
- `mcp==1.28.1` ← `crewai==1.15.28` requires
  `mcp~=1.28.1`; also ← `claude-agent-sdk==0.2.169`,
  `openai-agents==0.20.0`, `strands-agents==1.61.1`. CrewAI's pinned
  1.28.x range **does not permit** the reported 1.30.0 fix without an
  upstream dependency change.
- `uv==0.11.33` ← `crewai-cli==1.15.28` requires
  `uv~=0.11.6` ← `crewai==1.15.28`. The declared range does **not
  allow** the 0.13.4 patched version without a CrewAI upstream change.

**npm (historical dependency ancestry, now split between modern workspace and isolated v5 fixture):**

- **Historical modern workspace, before PR #98:** `@fastify/busboy@2.1.1`
  ← `undici@5.29.0` ← `@ai-sdk/provider-utils@3.0.41` ←
  `ai@5.0.272` ← dev-only `ai5` alias. **Current state:**
  these exact dependencies are absent from the modern
  `clients/typescript/bun.lock` and installed **only in**
  `clients/typescript/compat/ai-sdk-v5/` for isolated compatibility
  testing. Consumers installing the upstream AI SDK v5 may still receive
  this chain. Avoid forcing a major Busboy upgrade into Undici v5 without
  testing compatibility.
- `undici@6.29.1` ← AI SDK v6 developer/optional peer dependency and
  OpenAI SDK / LangSmith optional peers in the TypeScript test workspace;
  `undici@7.30.1` ← **dev-only** AI SDK v7 compatibility test alias.
  Bun 1.3.10 regenerated these entries and integrity checks after
  invalidating only their stale locked records; scoped semver-compatible
  selectors preserve the patched floors. The `undici@5.29.0` line
  remains **only in the isolated v5 fixture**, not the modern Bun lockfile.
- `esbuild@0.28.2` ← `tsx@4.23.15` ← TypeScript workspace and adapter
  **devDependencies**. Both are now above their verified patch floors;
  the source manifest declares `tsx ^4.23.9`.
- `uuid@11.1.1` ← Google ADK via A2A JS SDK; **also** `uuid@9.0.1` ←
  `gaxios@6.7.1` ← Google ADK's developer dependency tree. The 9.x copy
  means we must not dismiss the audit warning simply because 11.1.1 is
  also present.

**Interpretation:** The base Python wheel is dependency-free and installed
successfully in a fresh environment. All seven npm packages were inspected
with `npm pack --dry-run`, and their declared production dependency edges
contain only `@agentegrity/client` (or none, for the client). Those facts
reduce *direct distribution* exposure; they do **not** remove vulnerabilities
in consumer-selected framework peers or installations of the optional
`crewai` extra.

## Legacy AI SDK v5 isolated compatibility lane

**Completed in PR #98:** The AI SDK v5 test-only alias (`ai5@5.0.272`) was
moved from the modern `@agentegrity/vercel-ai` workspace
`devDependencies` into `clients/typescript/compat/ai-sdk-v5/`, which is
**outside** the published `packages/*` workspace. Its three actual v5
behavior tests are preserved, run in a separate Node 18/20/22 PR job with a clearly
labeled advisory audit, and remain visible to maintainers.

This is **dependency isolation**, not remediation of vulnerabilities in
`ai@5`, `undici@5.29.0`, or `@fastify/busboy@2.1.1`. The integration
still advertises compatibility with v5 and downstream applications
installing the affected SDK may remain exposed. Do not change the
v0.13.0 publication gate based only on the modern workspace audit
becoming cleaner.

To release with v5 compatibility, an authorized reviewer must either
establish a patched compatible dependency graph or explicitly accept
the residual **optional consumer-path** risk with rationale and owner.
An isolated test suite gives us accurate inventory; it is not a
substitute for upstream security maintenance.

## Upstream CrewAI remediation investigation

The last published CrewAI version checked (1.15.28) constrained

end-to-end integration checks.

## Enforced publication gate (follow-up to issue #97)

**Until a compatible upstream fix is available, Agentegrity cannot
patch CrewAI's dependencies or AI SDK v5's dependencies in place.**
We must neither force incompatible package overrides nor pretend
that moving the legacy test tree out of the modern Bun workspace fixes
consumer installations.

The tag-triggered `.github/workflows/release.yml` now includes a
**blocking `optional-dependency-security-gate` job**. Before its
TestPyPI publisher can start, the release workflow:

1. Installs the published optional `agentegrity[crewai]` extra in a
   clean Python runner and writes a full `pip-audit` JSON report.
2. Installs the isolated AI SDK v5 fixture and writes an `npm audit`
   JSON report, separately from the modern TypeScript workspace.
3. Runs `scripts/verify_release_dependency_audits.py`, which
   **fails on every unresolved reported vulnerability** (or malformed/
   missing audit evidence) and prints affected dependency names.
4. Retains both reports as a GitHub Actions artifact even on failure.

This job is not advisory: `publish-testpypi` has it as a dependency,
which also prevents its downstream PyPI/npm publication stages from
starting. A [nonpublishing rehearsal](https://github.com/Cogensec/agentegrity/actions/runs/39537584046)
confirmed that the real parser correctly **blocks** on the current reports:
**six Python advisory entries** (ChromaDB, MCP, uv) and **five affected
npm packages** in the isolated AI SDK v5 fixture (two high severity).
The rehearsal emits a warning rather than failing the PR; the tag-triggered
release gate exits nonzero and prevents publication. These scoped counts
should not be confused with the broader prior all-extras audit totals. Do not create the tag as a
test: run the nonpublishing validation and resolve issue #97 first.

The release gate has **no silent vulnerability ignore list** and no
automatic "accept optional CVEs" mode. An exception would require a
separate reviewed code/policy change, explicit documented approval,
and an impact/expiry decision. No such exception is presently approved.

### Supported integrations and mitigations until upstream fixes

- Base `pip install agentegrity` has no required Python runtime
  dependencies; the affected CrewAI components enter only when
  installing `[crewai]` (or `[all]`) or supplying a host with CrewAI
  already installed.
- Prefer framework-specific extras for deployments. Avoid installing
  `[all]` on production systems unless all included optional
  dependencies have been reviewed.
- Do not expose affected ChromaDB server APIs to untrusted clients.
  Restrict network access, authentication/authorization boundaries,
  and any remote model-loading features at the Chroma host itself.
  These are **deployment mitigations**, not proof that the upstream
  code-execution or tenant-isolation advisories are corrected.
- Don't expose vulnerable MCP stateful HTTP servers without strict
  trusted network boundaries and session/resource controls. Obtain a
  CrewAI release allowing the patched MCP when one becomes available.
- AI SDK v5 applications still need to patch or replace the
  upstream Undici 5/Busboy 2 dependency path; Agentegrity's adapter
  cannot change what the caller-installed AI SDK brings into its host.

## Current decision

**Prepared and mergeable release infrastructure is not the same thing as
approved distribution.** This triage is intentionally open. Closing this
release gate requires evidence of fixes or a documented, approved decision
about the affected optional dependency paths. Do not claim "0 known
vulnerabilities" and do not publish v0.13.0 on the strength of a green
advisory-only job.
