# Agentegrity v0.14.0 — Universal Agent Integrity release candidate

**Status: NOT PUBLISHED. No Git tag, PyPI upload, or npm publication has been authorized.**

This candidate packages the opt-in universal-agent work merged after the
v0.13.0 release, without changing existing agent integrations by default.

## What is included in source

- Versioned, metadata-only canonical lifecycle and tool-event contract with
  explicit, *claimed* source identity and capability levels.
- Trusted host lifecycle observer; opt-in only, not a universal interception mechanism.
- Host-owned action gateway with bounded task mandates, actual executor veto,
  scoped multi-agent delegation and in-process revocation.
- Python MCP `tools/call` enforcement wrapper. Not a deployed MCP proxy
  and not proof of arbitrary client interception.
- Canonical Pro HTTPS sender. Sends only when the application explicitly
  calls `send`, validates 202 receipts, and treats 409/retryable outcomes
  as ambiguous rather than as verified effects.
- Synthetic banking reference with denied financial actions and metadata-only
  receipt simulation. **No real bank or customer workflow tested.**

## Explicit release gates

1. Both `python scripts/check_versions.py` and
   `bun run check-versions` must report full parity.
2. Run complete Python/TypeScript CI, package/sdist checks, offline wheel
   install and npm pack checks on the **exact proposed release SHA**.
3. Execute real OSS sender -> authenticated Pro Preview -> PostgreSQL ->
   tenant-isolated fleet-read acceptance, including duplicate/replay
   behavior, payload rejection, and retention. An offline mock transport is
   not enough.
4. Resolve or explicitly disposition all fresh optional-dependency advisories
   under a **new, v0.14.0-specific** signed-off security risk policy.
   The v0.13.0 exception does not apply to this candidate.
5. Obtain explicit release-owner approval before tagging or publishing
   any Python or npm artifact, and verify registry availability.
6. Once the OSS version is published, rebuild both Pro lockfiles and run
   verified integration tests against `agentegrity==0.14.0` in a Preview.
   Do not install an unpublished version in the production Pro environment.

## What v0.14.0 does NOT certify

No independently verified workload identity, downstream transaction effect,
distributed delegation/revocation, durable recovery, automatic cross-agent
framework enforcement, or physical safety guarantee is asserted.

**Before approving the tag:** replace the version-specific release policy
references in `.github/workflows/release-candidate.yml` with v0.14.0
evidence and a separately authorized disposition. The existing
tag-triggered release workflow must fail closed on version/policy mismatch.
