# Agentegrity v0.13.0 — narrowly scoped security-risk disposition

**Decision:** Approved, conditionally and temporarily, for publication of
the **v0.13.0 OSS distribution artifacts only**. Not a determination that
the optional integrations are secure, and **not approval to deploy
vulnerable upstream services**.

**Authorization basis:** Explicit approval by the project requester on
2026-10-21 to document and approve a narrowly scoped risk disposition.
This statement records that request; it does not claim an independent
third-party audit or an approval by an unnamed security officer.

**Owner:** Cogensec release owner (responsible for release and eventual
upstream resolution). **Start:** 2026-10-21. **Expiry:** 2026-11-20 (inclusive).
**Scope:** v0.13.0 only. **Reapproval:** Mandatory on expiry, new findings,
changes to affected package versions, a broader deployment, or a new release.

The machine-readable, exhaustively enumerated record is
[`v0.13.0-risk-disposition.json`](v0.13.0-risk-disposition.json).
The [release audit verifier](../../scripts/verify_release_dependency_audits.py)
compares every allowed Python package/version/advisory ID, every legacy npm
package/severity/advisory/transitive dependency reference, and three known
installed npm versions against the current audit. No broad `--ignore-vuln`,
environment switch, wildcard exception, or severity cutoff is permitted.
Any new/changed finding or unparseable evidence is **NO-GO**.

## What is, and is not, accepted

This is a conscious **residual supply-chain disclosure/distribution
decision** for an OSS library that does not bundle or require these
upstream components by default. A consumer who chooses affected
third-party framework installations still inherits the upstream risks.

| Affected opt-in path | Evidence and residual risk | Scope decision |
| --- | --- | --- |
| `agentegrity[crewai]` → ChromaDB 1.5.9 | Four advisory IDs, including code injection and tenant-isolation weaknesses; no verified patched stable release | Accept distributing optional metadata **only**. Do **not** authorize externally accessible affected Chroma Python server routes or cross-tenant production workloads |
| CrewAI → MCP 1.28.1 | One reported resource exhaustion/session handling advisory; patched MCP available, but published CrewAI pins an incompatible series | Accept distribution of the optional connector **only**. Do not approve vulnerable stateful HTTP endpoints or unbounded session exposure |
| CrewAI CLI → uv 0.11.33 | One reported compromised-root-certificate/TLS trust advisory; published CLI pins incompatible with patched uv | Accept packaging metadata **only**, not privileged installer execution or package acquisition under the affected trust model |
| Isolated AI SDK v5 fixture / consumer-provided `ai@5` | Five vulnerable npm package entries, including high-severity Undici and Busboy advisories | Accept retention of the optional v5 adapter API and isolated test coverage **only**. Does **not** authorize production applications to use unpatched vulnerable HTTP/streaming paths |

**High-severity residual risk is real.** No statement of zero
vulnerabilities, patched upstream behavior, secure production deployment,
or CVE immunity is permitted.

## Required controls

- Continue shipping Python's base wheel with **zero required
  dependencies**; do not vendor CrewAI/Chroma/MCP/uv into the wheel.
- Verify all seven npm tarballs have **no** legacy AI SDK v5, Undici 5,
  or Busboy 2 **required runtime** dependencies.
- Keep the separately installed AI SDK v5 tests in the Node 18/20/22
  compatibility matrix. Tests demonstrate behavior, not security.
- In deployment instructions recommend modern patched framework versions,
  isolate legacy services, and avoid exposing affected Chroma Python server
  paths or MCP stateful transports to untrusted parties.
- Disclose advisories to operators; downstream teams need their own
  environment-specific risk review before running the optional packages.
- Preserve `pip-audit` and `npm audit` JSON, exact legacy npm version
  snapshot, and approved/disallowed decision in every candidate review.
- Require code review and CI on changes to the exception policy or
  verifier; never auto-approve an expanded exception.
- The release owner must separately verify the exact commit, package and
  registry readiness, security notice, and issue #106 checklist, then
  explicitly authorize the exact `v0.13.0` tag.

## Exit and revocation

This disposition automatically stops being valid after 2026-11-20.
It is invalidated **immediately** by any advisory difference, version
drift, broader dependency reachability, scope change or credible new
evidence of direct Agentegrity exploitability. Updates require a new
explicitly reviewed risk decision, not merely a CI green status.

**Release readiness remains distinct.** Merging this disposition and
passing its automated gate does **not** constitute permission to create
the tag. The tag triggers TestPyPI, PyPI and npm publication; an explicit
owner **GO for the exact release SHA** remains necessary.
