# Agentegrity v0.13.0 — Runtime Authority and Evidence Integrity

**RELEASE CANDIDATE — NOT PUBLISHED.** This document is prepared for a future
GitHub release and must not be read as an announcement that v0.13.0 is already
available on PyPI or npm. The last published release is v0.12.0.

**Full changes:** [v0.12.0...main](https://github.com/Cogensec/agentegrity/compare/v0.12.0...main)
**Detailed migration and fixes:** [CHANGELOG](../../CHANGELOG.md)

Agentegrity now pairs integrity evaluation with **opt-in task-bound authority**
at trusted action boundaries and explicit accounting for downstream effects.
The release also corrects previously ineffective enforcement paths, makes
assurance claims more precise, and strengthens evidence-preserving recovery.

## Highlights

### 1. Task-bound Runtime Action Authority (experimental, Python OSS)

`TaskMandate`, `ToolAuthority` and `ActionSecurityGate` provide short-lived,
run-bound permission scopes over tools, resources, effects and credentials.
`invoke()` and `ainvoke()` authorize at the host-installed execution
boundary, rather than assuming every framework hook can stop an action.
Unauthorized executions do not create invented effect receipts.

### 2. Trust boundaries and data-as-control protection

`ActionProvenance` and `TrustBoundaryPolicy` check host-supplied control
lineage so retrieved documents, tool outputs, memory and peer messages are
not automatically promoted from untrusted data to protected tool authority.
The host must collect accurate, trusted provenance; there is no automatic,
complete taint-tracking guarantee.

### 3. Bounded delegation for multi-agent systems

`ActionSecurityGate.delegate()` creates narrower child grants, constraining
scope, identity, lifetime, depth and inherited revocation. Delegation is
disabled by default and remains **process-local**, not a signed
cross-process capability system.

### 4. Late-arriving evidence and explicit uncertainty

Effect receipts distinguish `PENDING`, `UNKNOWN`, `CONFIRMED`, `FAILED`
and `CONFLICTED`. Added `evidence_timeout`,
`expire_unresolved_effects()`, `EffectObservation` and
`effects_verified()`. A successful tool result is not verified downstream
success. Confirmed/failed outcomes require a trusted host verifier that checks
independent, authenticated effect records. Process-local receipts are neither
durable nor a signed production evidence ledger.

### 5. Enforceable adapter boundaries and deny-and-continue

Previously advisory `enforce=True` paths now stop supported calls in
LangChain/LangGraph, OpenAI Agents SDK, CrewAI and Google ADK. New LangChain
middleware and ToolNode wrappers, OpenAI function-tool guardrails, and Google
ADK runner/workflow plugins cover additional tool surfaces. Deny-and-continue
returns a stable error result where supported. Some adapters necessarily raise;
AutoGen and the Bedrock boto3 observation path cannot stop the call.
Host-specific tool and handoff gaps remain.

### 6. Security, reporting and recovery correctness

- Approval denials no longer pass by treating `ApprovalDecision` as truthy.
- GOV-002/GOV-003 now identify configured code execution and financial tools.
- Optional model-backed adversarial/SLM evaluation runs at supported async
  pre-tool gates instead of silently falling back to synchronous pattern checks.
- Signed/unsigned/trusted chain states are distinguished with
  `chain_signatures`; sessions with no chain report `chain_hash_linked: null`.
- Claude Code and Codex hook chains can use local Ed25519 signing.
- Recovery measures only backed mechanisms and preserves compromise evidence
  during checkpoint restoration.
- HTTP exporters reject remote plaintext HTTP and redirects; TypeScript event
  reporting does not default to an unrequested localhost destination.
- Fixes address shell classification, CrewAI concurrency/subscription cleanup,
  ADK and Agno tool-result handling, OpenAI tool-argument capture, alert exports
  and event-schema compatibility.

### 7. Documentation and distribution

The redesigned README includes tested synthetic authorization output, accessible
architecture/demo SVGs, framework capability distinctions and PyPI/npm download
badges. The [Agent Ecosystem Integration Roadmap](../AGENT-ECOSYSTEM-ROADMAP.md)
sets out a research and engineering plan for enterprise, financial, customer,
browser, infrastructure, research, coding, multi-agent and eventually embodied
AI systems. **These additional integrations are not shipped in v0.13.0.**

## Before upgrading: breaking changes

1. **`enforce=True` actually blocks more actions.** Callers relying on the
   former dry-run behavior must set `enforce=False`. Tool-evaluation errors
   also deny under enforcement mode.
2. **Denied-call results:** `on_deny="continue"` becomes the default where
   supported. Use `on_deny="raise"` only for integrations that implement
   termination; model-visible details are reduced to stable reason codes.
3. **Governance rules:** GOV-002/GOV-003 may now require approvals for inline
   code execution and financial operations. Configure `sandboxed`,
   code-execution/financial tools and approval handlers before deploying.
4. **Adapter API:** Adapter-level `api_key` was removed. Use
   `AgentegrityClient(prefer_llm=True, api_key=...)` or configure the layers.
   `CrewAIAdapter.subscribe(legacy_task_mapping=...)` is removed.
   Synchronous built-in layers no longer expose a redundant `aevaluate()`.
5. **Framework minimums:** The `openai-agents` extra requires
   `openai-agents>=0.8.0`; `agno` requires `agno>=3.1`.
6. **Exporters:** Python HTTP export requires HTTPS or loopback; TypeScript
   reporters require an explicitly configured URL. `AdapterConfig.defaultBaseUrl`
   is removed, `ReporterOptions.baseUrl` is optional, and redirects are blocked.
7. **Evidence/recovery:** `chain_hash_linked` may be `null`.
   Recovery scores can decrease when claimed capabilities have no real backend.
   Checkpoint restore validation and evidence preservation are stricter.

## Known limitations

- Observing, evaluating, authorizing and independently verifying are
  different capability levels. A host without a real tool veto is observation
  only, even if Agentegrity evaluates its events.
- Source provenance must be captured by a trusted host, and authorization
  must be enforced at a controllable tool boundary. Server-side and hidden
  tool actions may not be interceptable.
- Coding-agent hook daemons have documented fail-open timeout behavior;
  some fallbacks lose cross-call state.
- Delegation, receipts and evidence-reconciliation state are process-local.
  The host must call timeout sweeps; there is no durable distributed ledger.
- Cryptographic assurance requires pinned trusted keys, not merely a
  hash-linked chain or locally generated signature.
- No results are claimed for the planned 100-run synthetic banking evaluation
  until it has actually been executed and independently reviewed.
- Embodied and physical-system safety integrations are a future research
  direction and are not production-certified.
